# My Journal / Retained Notes

The Journal is a normal free study tool. A player who has not encountered a story fragment sees only personal notes. On focus the Journal derives read-only recovered entries from the existing persisted discovery flags, including the Shop traces, actual chart, signed inventory label, practice margin, notebook, field-note documents, recovered draft and ending. No extra collection tap is necessary. The neutral heading becomes Nora’s Notes only after Session 017. Red ink uses the bundled Reenie Beanie font (SIL OFL), a looser, irregular handwritten print style with larger text for legibility; ordinary notes use the current app theme. No real journal text is sent to Ask Nova or posted publicly. Sharing/printing is per selected entry and user-initiated.

Personal note sync uses owner-scoped device storage and the journal_notes table with row-level access. Drafts are local; saved notes are synchronized when connected. Offline edits are queued; concurrent edits to the same note are last-write-wins at sync time, not collaborative editing. Guest notes do not sync. Account deletion cascades to cloud notes and clears local journal keys. ARG discovery state now uses separate device-local guest and authenticated-account namespaces. Ask, Island, Shop detail, Focus Practice, Field Notes, the evidence screen and Journal use the originating account for their clue operations. Relevant screens remount when identity changes. Legacy unowned discovery keys are retained but not automatically imported, as ownership cannot be established. Guest story progress is separate by default. A signed-in Journal user may explicitly confirm a one-time device-local import of their own guest discoveries. The transfer keeps existing account records, never uploads guest personal notes or grants rewards, leaves the guest record intact, and binds interrupted imports to the original destination. This is local convenience, not a cross-device security boundary. Guest progress from a shared device must not be imported without ownership confirmation. Cross-tab concurrent import has not been verified. Account deletion removes its local clue keys. Recovered clues are derived, not personal cloud notes; cross-device story synchronization is not implemented.

## Reward security release gate
The old API accepted two fixed phrases as proof, allowing an authenticated client to attempt a claim without playing. The candidate endpoint now fails closed unless a trusted account-bound completion verifier is wired in **and** the existing reward feature switch is enabled. No verifier is wired yet: actual claims remain closed in this candidate; the database allocation function remains unchanged. Before release, implement independent server-side progression/eligibility, replay and concurrency checks; a copied client flag or imported local history must never qualify by itself. Existing production code and reward settings were not changed. Mocked endpoint tests and disposable SQL allocation tests are distinct from signed-in end-to-end verification.
The release candidate client also returns a closed receipt without contacting an older backend. This is a temporary hard gate, not a completed eligibility implementation. Remove it only after the trusted verifier and staging E2E checks pass.

## Server verification candidate
Four short, story-derived questions appear in the normal Ask Nova exchange after Session 017 (no AI credits or repeatable XP). The database chooses their order and holds the current nonce, progress, failure count and verification timestamp. Five incorrect answers trigger a 15-minute cooldown. The current nonce is account-bound, rotates after an answer and cannot advance twice; replaying Session 017 resumes. The new backend takes the account from the verified bearer token, not the request body. The reward transaction itself refuses new unverified claims, even through the legacy RPC. Existing receipts remain intact. No answers or personal journal text are stored by the verifier. Local imported discoveries do not grant verification. This verifies knowledge, not proof of human participation; answer sharing and multi-account abuse still need assessment. The client and backend feature switches stay off until staging tests and review. The questions are an optional reward debrief, not a requirement for finishing the free story. Review the extra conversational friction with blind playtesters.
